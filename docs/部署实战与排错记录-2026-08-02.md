## 2. 代码修复（关键，勿回退）

| 文件 | 修复 | 为什么 |
|------|------|--------|
| `overlay/server/src/server.rs` | `/register` 路由：`"/login" \| "/register" => auth/login.html` 拆成两条，register → `auth/register.html` | 注册页一直显示登录页 |
| `overlay/server/src/mail.rs` | SMTP 传输：port≠465 用 `starttls_relay`，465 用 `relay` | Resend 587 是 STARTTLS，原 `relay()`（隐式 TLS）握手报 `InvalidContentType` |
| `overlay/server/Cargo.toml` | lettre 用 `tokio1-rustls-tls`（**不是** native-tls） | native-tls 依赖系统 OpenSSL，破坏 musl 静态部署；rustls 无此依赖 |
| `scripts/e2e-auth.sh` | 适配邮箱验证：register 后从日志取 verify token → verify-email(302) → login → me | 新注册流程要求邮箱验证后才激活 |

**SMTP 排错要点**：`smtp.resend.com:587` 是 STARTTLS。lettre 里：
- `.relay()` → 端口 465 隐式 TLS
- `.starttls_relay()` → 端口 587 STARTTLS（Resend 用这个）
- native-tls 会报 `wrong version number`（TLS 协商不兼容），**必须用 rustls**，且 musl 静态才成立。

## 3. 免 sudo 的 musl 交叉编译（本机一次性搭好）

> 文档 `低配机交叉编译CLI.md` 用 `sudo apt install musl-tools`。本机 sudo 要密码，改用**免 sudo** 方法，等价可用：

```bash
# 1. 下载并解包 musl 三件套（apt download 无需 sudo）
cd /tmp && apt download musl-tools   # 得到 musl-tools.tar.gz（离线包）
tar -xzf musl-tools.tar.gz && cd musl-tools
dpkg -x musl-tools_*.deb mt && dpkg -x musl-dev_*.deb dev && dpkg -x musl_*.deb musl

# 2. 建本地前缀 + 打补丁 specs（把 /usr/ 路径改成本地）
MUSL_PREFIX=$HOME/.local/musl
mkdir -p $MUSL_PREFIX/{lib/x86_64-linux-musl,include/x86_64-linux-musl,bin}
cp dev/usr/lib/x86_64-linux-musl/* $MUSL_PREFIX/lib/x86_64-linux-musl/
cp -r dev/usr/include/x86_64-linux-musl/* $MUSL_PREFIX/include/x86_64-linux-musl/
sed -e "s|/usr/lib/x86_64-linux-musl|$MUSL_PREFIX/lib/x86_64-linux-musl|g" \
    -e "s|/usr/include/x86_64-linux-musl|$MUSL_PREFIX/include/x86_64-linux-musl|g" \
    dev/usr/lib/x86_64-linux-musl/musl-gcc.specs > $MUSL_PREFIX/lib/x86_64-linux-musl/musl-gcc.specs
cat > $MUSL_PREFIX/bin/musl-gcc <<EOF
#!/bin/sh
exec x86_64-linux-gnu-gcc "\$@" -specs "$MUSL_PREFIX/lib/x86_64-linux-musl/musl-gcc.specs"
EOF
chmod +x $MUSL_PREFIX/bin/musl-gcc

# 3. 仓库 .cargo/config.toml（gitignored）指向它
cat > ~/overseas-github/llm_wiki-server/.cargo/config.toml <<EOF
[target.x86_64-unknown-linux-musl]
linker = "$HOME/.local/musl/bin/musl-gcc"
EOF
```

**编译必须设 PROTOC**（lancedb 的 build script 需要；用仓库自带 vendored protoc）：
```bash
cd ~/overseas-github/llm_wiki-server
export PROTOC="$PWD/.tools/protoc/bin/protoc"
cargo build --release --target x86_64-unknown-linux-musl --manifest-path overlay/server/Cargo.toml   # ~7-12 min 增量
cargo build --release --target x86_64-unknown-linux-musl --manifest-path overlay/cli/rust/Cargo.toml
```
验证：`file` 应显示 `static-pie linked`，`ldd` 为空。产物：
- `overlay/server/target/x86_64-unknown-linux-musl/release/llm-wiki-server`（55M）
- `overlay/cli/rust/target/x86_64-unknown-linux-musl/release/llm-wiki`（50M）

## 4. deploy-ecs.sh 增强（本次新增能力）

| 能力 | 说明 |
|------|------|
| `SMTP_PASS` env | 设置后注入 systemd `Environment=SMTP_PASS=...`（配合 config `"pass":"${SMTP_PASS}"` 展开） |
| `LLM_WIKI_AUTH_DB` | 默认 `${SERVER_REPO}/auth.db`（**跟随仓库，避免覆盖已有用户库**），可 `SERVER_AUTH_DB=` 覆盖 |
| 完整 auth env | `REQUIRE_LOGIN`/`ADMIN_EMAIL`/`DAILY_CHAT_LIMIT`/`SESSION_TTL`/`PUBLIC_LANDING_DIR` 全部注入 unit（否则重部署丢手工配置） |
| rsync `overlay/static` | **旧脚本漏了 static**（systemd 却引用它）→ 落地页一直旧版；已补 `--delete` 同步 |
| `CONFIG_LOCAL` 覆盖 | `CONFIG_LOCAL=overlay/config/server.xxx.local.json` 用 per-server 真实配置（勿用 `server.example.json` 模板，项目路径/token/LLM 全是占位符） |
| `SKIP_SYSTEMD=1` | 只传文件 + 生成 unit 到 `${SERVER_REPO}/llm-wiki-server.service`，不写 /etc、不重启（用于无 sudo 用户如 ecs199 的 li） |

**部署要点**：
- `server.example.json` 是纯模板（项目 `/path/to/...`、token `change-me`、LLM `api.example.com`）。**直接部署会覆盖坏配置**——必须先基于远程真实配置构建 `server.<host>.local.json`（gitignored），再用 `CONFIG_LOCAL=` 指定。
- 部署前读远程 `server.local.json` 复用真实项目路径/token/LLM key，只加 smtp 块，避免破坏现状。
- 远程已有 auth DB 时，`SERVER_AUTH_DB` 必须指向原路径（幂等迁移自动兼容旧用户）。

## 8. 排错速查（本次踩的坑）

| 现象 | 根因 | 解决 |
|------|------|------|
| `ssh -o BatchMode=yes` 到 ecs199 超时挂起 | BatchMode 触发交互 auth 路径挂起 | **去掉 BatchMode**，用带 `IdentityFile` 的 config 片段直连 |
| SSH 多命令（journalctl 全量/sqlite3/health?deep）超时 | 部分远程命令挂起 | 拆成单命令 + `timeout`；`journalctl` 加 `--since "N min ago"` |
| `pkill -f 'llm-wiki-server'` 把自己 shell 杀了（exit 144） | 命令行里含目标字符串被匹配 | 用 `pkill -f 'llm-wiki-serve[r]'`（括号破匹配）或拆开执行 |
| musl 编译报 `Could not find protoc` | lance/arrow 的 build script 需要 | `export PROTOC="$PWD/.tools/protoc/bin/protoc"` |
| SMTP `InvalidContentType`（rustls） | `relay()` 对 587 隐式 TLS 不匹配 | 改 `starttls_relay()`（见 §2） |
| SMTP `wrong version number`（native-tls） | native-tls TLS 协商不兼容 | 回 rustls（见 §2） |
| 注册返回"验证邮件已发送"但收不到 | from 用 resend.dev 测试域只能发账号邮箱 | Resend 验证域名后 from 改 `noreply@<域名>` |
| `/register` 显示登录页 | `server.rs` 路由 `/login|/register` 都指 login.html | 拆开（见 §2） |
| 远程落地页旧版 | deploy 脚本没 rsync `overlay/static` | 补 rsync（见 §4） |
| 部署后项目 current 是父目录 | `LLM_WIKI_PROJECT=SERVER_WIKI_ROOT`（父目录） | 已知现象，非阻塞；必要时把 LLM_WIKI_PROJECT 指向具体项目 |
| health `authDb:null` | 显示字段问题（auth 实际可用，注册/me 正常） | 非阻塞 |
