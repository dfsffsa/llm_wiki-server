# 竞品调研提示词 — 知识库 AI 问答产品

## 调研目标

请搜索并整理以下产品的信息。我们的产品是一个**自托管、私密的知识库 AI 问答系统**：用户在本地有 wiki 目录(标记文件),系统把资料 ingest 后支持自然语言问答、全文搜索、知识图谱。技术栈: Rust 后端 + 静态 JS 前端(无框架,纯 HTML + 原生 JS)。

**核心想了解的是:这些竞品的前端界面设计、交互模式、用户体验思路——不是功能列表,而是「为什么这么设计」。**

## 调研方向

### 1. 直接竞品:开源自托管知识库

请搜索并整理以下产品的**前端交互设计分析**,每个产品重点看:

- **界面布局**: 主页是聊天还是文件浏览? 左侧是会话列表还是目录树? 搜索入口在哪?
- **问答交互**: 消息气泡怎么展示? 流式输出怎么做? 推理过程/思考链怎么展示?
- **知识库浏览**: 怎么展示文档结构? 怎么在回答中关联引用原文? 引用标记怎么做?
- **搜索体验**: 搜索结果怎么展示(列表/卡片)? 搜索和聊天怎么切换? 有没有类似 RAG 的"检索来源"展示?
- **移动端**: 有专门的移动适配吗? 导航怎么折叠?

重点关注产品(每组至少看 2-3 个):

**A 组:开源且活跃**
- Danswer / AnswerAI
- Quivr / Quivr
- RagFlow
- MaxKB
- Dify(虽然是 AI 工作流平台,但对话 UI 可以参考)
- AnythingLLM

**B 组:商业但设计优秀**
- Notion AI(知识库问答的标杆)
- Mem.ai
- Google NotebookLM
- Perplexity(特别是 Spaces/Collections 功能)
- Sourcegraph Cody

### 2. 前端交互模式(横比分析)

不要只列功能,请做横向对比:

**a) 初始页面**
- 打开产品后第一眼看到什么? 聊天输入框? 项目/空间列表? 建议问题?
- 我们的 lite 页目前是"选项目→进入聊天",竞品怎么做的?

**b) 思考/推理展示**
- 当 LLM 在推理时,界面怎么体现"正在思考"?
- DeepSeek R1 风格(ChatGPT 网页)展示完整推理链? Perplexity 展示搜索步骤? 还是只显示最终回答?
- 我们的 lite 页已经有可折叠的"思考过程"面板,竞品有没有更好的交互范式?

**c) 引用和来源标注**
- 回答中的引用怎么标注(角标 [1][2]? 行内链接? hover 弹窗?)
- 点击引用后是浮窗预览原文、滚动到原文、还是跳转?
- 怎么样体现"这个回答基于哪些文档"?

**d) 搜索与问答的关系**
- 搜索和问答是同一个入口(像 Perplexity)还是分两个模式?
- 搜索结果点击后是打开原文还是继续对话?
- 我们的产品有独立的 `/api/v1/search` 端点,但 lite 页没有搜索入口——竞品怎么平衡这两个功能?

**e) 移动端适配**
- 是否有响应式布局? 侧边栏在手机上怎么处理?
- 输入框是否固定在底部?
- 有没有 PWA / 离线能力?

### 3. 我们做了但可能改进的设计点

以下是我们 lite 页已有的设计,请对比竞品看能不能找到更好的范式:

| 我们已有的 | 想找更好的 |
|---|---|
| 主页是项目卡片选择(类似 ChatGPT 的模型选择) | 竞品是不是直接把用户丢进对话?"选知识库"这一步能否省略? 或者有其他更好的方式? |
| 左侧历史会话侧边栏(类似微信) | 侧边栏在窄屏折叠为汉堡菜单,竞品有没有更好的方案? |
| 消息气泡中可折叠的"思考过程"面板 | 竞品怎么处理 reasoning? 是隐藏、折叠还是直接展示? |
| 顶部用户栏:邮箱 + 剩余额度 | 竞品怎么展示配额? 有没有更优雅的方式? |
| 打字机逐字输出(RAF + 纯文本→最终 markdown) | 竞品的流式渲染有没有更好的体验? |
| RAG 检索资料作为 system message 注入 | 竞品怎么展示"基于哪些资料回答"? 引用标记怎么交互? |

### 4. 我们还没做的功能,竞品做得好的

- **落地页/首页**: 未登录用户看到什么?
- **引导体验**: 新用户首次使用,竞品怎么引导(空状态、建议问题、onboarding)?
- **主题/个性化**: 竞品支持深色模式吗? 多主题? font 设置?
- **键盘快捷键**: 竞品支持哪些快捷键(⌘K 搜索, ⌘Enter 发送, Esc 取消)?
- **搜索体验**: 我们的搜索是独立 API 但 lite 页没有搜索 UI——竞品的搜索入口和交互范式是什么?

### 5. 技术实现上值得参考的

- **前端框架选择**: 为什么这些产品选了 React/Vue/原生? 对性能有什么影响?
- **SSR vs SPA**: 内容页(首页)和服务页(聊天)是否用了不同的渲染策略?
- **构建与部署**: 有没有类似我们"纯静态+零构建"的 lite 页方案?
- **响应式策略**: 是桌面优先还是移动优先?

## 输出要求

1. 每个竞品给出: 一句话定位 + 界面截图描述 + 3 个值得借鉴的设计点
2. 横向对比部分: 用表格对比 3-5 个竞品在某个维度上的做法
3. 最终给出: **Top 3 最值得我们借鉴的设计模式**,并说明为什么(适配我们"纯静态前端+Rust 后端+自部署"的技术约束)

## 我们的约束条件(筛选建议时需要匹配)

| 条件 | 说明 |
|---|---|
| 自部署 | 不能依赖 SaaS 服务,必须 self-hosted |
| 轻量前端 | 纯 HTML + 原生 JS,无 React/Vue/SPA 框架 |
| 单进程 | Rust + tiny_http + SQLite,无额外服务 |
| 核心场景 | 知识库问答(先有文档,再问答),不是聊天机器人 |
| 用户特点 | 小团队或家庭使用,不是企业级 SaaS |
