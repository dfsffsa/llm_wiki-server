# 国际化（i18n）— 公开页面中英文双语

> 公开页面（landing / auth 三页 / lite QA 页）支持**中文 + 英文**，按浏览器语言自动显示，用户可手动切换。英文用户（北美部署 glb.sship.online 的目标用户）不再被中文界面挡住。

## 1. 机制：i18n.js = 唯一文案源

- 所有用户可见文字集中在 **`overlay/static/i18n.js`** 的 `COPY` 字典，每条 key 含 `zh` + `en` 两版。
- 页面 HTML **不写任何文案**，只用 `data-i18n` 属性引用 key：

```html
<span data-i18n="hero.cta.start"></span>                    → 文本
<input data-i18n-placeholder="lite.search.placeholder">      → placeholder
<a data-i18n-title="...">…</a>                              → title 提示
<div data-i18n-html="auth.login.agree">…</div>              → innerHTML（含链接 / <br>）
<meta data-i18n-meta-content="home.metaDesc">                → meta description
<button data-i18n-aria-label="lite.send.aria">↑</button>    → aria-label
<span data-i18n-toggle></span>                              → 语言切换按钮（放页面布局中）
```

- `<title>` 不写死在 HTML：i18n.js 用 `PAGE_TITLE.<page>` key + 品牌名拼出 `document.title`（首页 `DocuChat - <suffix>`，其他页 `<label> - DocuChat`）。HTML 里只留 `<title>DocuChat</title>` 作为无 JS 回退。

## 2. 改文案怎么办（核心工作流）

| 要做什么 | 改哪里 |
|---------|--------|
| **换品牌名** | 改 `i18n.js` 的 `brand.name.zh/.en` 一行 → 全站 logo、标题同步变 |
| **换 slogan** | 改 `i18n.js` 的 `brand.tagline` 一行（landing Hero 标题） |
| 改按钮/标签/段落 | 改对应 `copy.<key>.zh` / `.en` 一行，页面立即生效，**无需改 HTML** |
| 加新文案 | 往 `COPY` 加 key + 页面加 `data-i18n="key"` |
| 本地化服务端错误 | 往 `ERRORS` 加 `error.code` 对应条目 |

字典按页分组命名（`brand.*`、`hero.*`、`use-cases.*`、`features.*`、`steps.*`、`pricing.*`、`faq.*`、`auth.login.*`、`auth.register.*`、`auth.reset.*`、`lite.*`），方便定位。

## 3. 语言检测优先级

```
?lang=en           → 显式指定（写进 localStorage 持久化）
localStorage.lang  → 用户手动切换过的选择
navigator.language → zh* 开头 → 中文，其余 → 英文
```

页面右上角/导航栏有 `🌐 EN` / `🌐 中` 切换按钮（i18n.js 自动渲染进 `data-i18n-toggle` 元素）。

## 4. 服务端错误消息本地化

Rust 侧错误消息**保持中文不翻译**（避免与 billing 对 auth 的改动冲突）。客户端按 `error.code` 用 `ERRORS` 字典本地化：

```js
// error 形如 { code, message }
I18N.localizeServerError(errData.code, errData.message || I18N.t('...'))
```

- 有 `ERRORS[code]` → 返回本地化文本；
- 未知 code → 回退服务端原始 `message`。

错误码对应 `overlay/auth/src/error.rs` 的 `AuthError::code()`（`invalid_credentials`、`email_not_verified`、`rate_limited`、`daily_limit_exceeded` 等 14 个）。

## 5. LLM 回答语言（lite）

lite 页发送消息时，system prompt 按当前语言生成：

- 中文用户 → `用简洁中文回答…`
- 英文用户 → `Answer concisely in English…`

即英文用户问问题，拿到的也是英文回答。检索资料的分隔标记也本地化（`lite.systemPrompt.contextLabel`）。

## 6. 部署

- server 新增 `/i18n.js` 路由，从 `LLM_WIKI_PUBLIC_LANDING_DIR` 服务（与 `landing.js` 同模式）。
- `overlay/static/` 由部署脚本整体 rsync（`deploy-ecs.sh` / `sync-artifacts.sh`），i18n.js 自动带上。
- **lite 是构建产物**：改 `overlay/static/lite/` 后需重新构建才能进部署：

```bash
VITE_BACKEND=http VITE_API_TOKEN=... ./scripts/build-web.sh   # 把新 lite 复制进 upstream/dist/lite
```

## 7. 实现要点

- 加载：每页 `<script src="/i18n.js" defer></script>`。defer 保证在 DOM 解析完成、内联脚本执行后运行——所以 auth 页内联脚本先解除 banner 隐藏、i18n.js 再翻译，顺序正确。
- 切换按钮用内联样式（CSS 变量带回退：`var(--bg, #fff)`），在 landing/auth（Tailwind）和 lite（自定义主题）上都能融入。
- `setLang` 会派发 `i18n:changed` 事件；lite 的 `app.js` 监听它刷新动态文本（用量、占位符、空态问候）。
- 语言切换只重渲染静态文案；已显示的错误消息不追溯翻译（当前语言下显示即正确）。
- 未知 key 时 `I18N.t` 原样返回 key，便于发现漏配。

## 8. 踩坑记录（开发实测，2026-08-02）

| 坑 | 现象 | 解法 |
|----|------|------|
| **静态文件 1h 缓存** | 服务器对静态文件发 `Cache-Control: max-age=3600`。i18n.js 是"唯一文案源"，改 slogan 刷新不生效，被缓存 1 小时 | `server/src/static_files.rs` 的 `serve_file` 对 `rel == "i18n.js"` 特判返回 `no-cache`；其余文件保持原缓存。若将来新增高频更新的静态文件，同样处理 |
| **`data-i18n` 会清空子元素** | reset.html 把 `data-i18n` 放在 `<label>`（含子 `<input>`）上，`applyTranslations` 用 `textContent` 赋值直接 wipe 掉 input，表单字段消失 | `data-i18n`/`data-i18n-placeholder` 只放**叶子元素**；label 文案包成 `<label><span data-i18n="...">文案</span><input ...></label>`。含链接/换行的整句用 `data-i18n-html`（内容来自本地字典，无 XSS） |
| **`I18N.lang` stale** | 翻译引擎内部用闭包 `LANG` 所以切换正常，但 `setLang` 若不同步更新 `I18N.lang`/`I18N.isZh`，外部代码读它们会拿到旧值 | `setLang` 里同时更新 `I18N.lang`/`I18N.isZh`（已修复）。外部代码优先用 `I18N.t()` / `I18N.tpl()`，少直接读 `I18N.lang` |
| **server 编译慢** | release profile 用 `-C lto` + `codegen-units=1`，改 server 源文件触发整 crate 重链接，7-10 分钟 | 改 server 源码前把改动攒齐一次编译；纯前端改动（overlay/static）用旧二进制即可实测，无需重编译 |
| **lite 无 node_modules 跑不了 build-web.sh** | worktree/CI 环境没有 `upstream/node_modules`（gitignore），`build-web.sh` 无法执行，新 lite 进不了 `dist/lite` | 开发时把 `overlay/static/lite/.` 手动复制到临时 static 目录 + 生成 `config.js` 即可浏览器实测；部署前在有 node_modules 的机器跑 `build-web.sh` |
