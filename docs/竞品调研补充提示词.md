# 竞品调研补充提示词 — 知识库 AI 问答产品(第2轮)

这份提示词基于第1轮报告的缺口补充。请在报告中补充以下方面的内容。

## 补充一:缺漏的竞品分析

以下产品在第1轮中缺失,每个至少给出一句话定位 + 界面布局描述 + 2-3个值得借鉴的设计点。

### Dify
- 对话页面、知识库接入、引用是怎么展示的?
- 它的「工作室」和「对话」两种模式,切换逻辑是什么?
- 知识库文件的 Chunk 预览页面,怎么展示分段、置信度? 有没有可以直接参考的 UI 模式?

### Sourcegraph Cody
- 回答中的代码文件和行号引用是怎么标注的? 引用标记的交互方式?
- 它怎么让用户「确认回答基于哪些文件」? 来源展示的交互范式?

### Cursor / Zed AI
- 对话中怎么引用上下文文件? 文件名、代码片段在回答中怎么展示?
- 有什么轻量的引用UI模式(不需要IDE,纯Web端也可以用)?

### 问问 AI 中文产品(Kimi / 元宝 / 豆包知识库等)
- 知识库问答的界面和对话有什么区别? 引用来源怎么展示?
- 它们有没有「知识库主页」? 怎么选择不同的知识库?

## 补充二:搜索结果页面的交互设计

第1轮提到了统一输入框/搜索+问答双模式,但没有展开搜索结果页面本身的设计。请补充:

- **Perplexity**: 搜索结果页和问答结果页分别长什么样? 搜索结果的摘要、来源链接、图片是怎么排版的?
- **Google / 百度传统搜索**: 摘要截断、关键词高亮、分页/无限滚动——这些模式中哪些可以复用到知识库搜索?
- **Dify 知识库搜索**: 搜索结果怎么展示 Chunk 片段? 有没有关键词高亮? 怎么跳到原文?

分析后给出: **知识库搜索结果页的设计建议**,至少包含:
- 摘要怎么截断(字数限制? 围绕搜索词的上下文窗口?)
- 关键词高亮用 `<mark>` 标签实现?
- 结果排序是列表还是卡片? 需要哪些元信息(文件名、文件路径、更新时间、置信度分数)?

## 补充三:空状态 / 新用户引导设计

第1轮提到「直接丢进空聊天框会让用户困惑」,但没有展开竞品的空状态设计。请分析:

- **Notion AI Q&A**: 未回答前,搜索栏里有什么 placeholder? 有没有推荐问题列表?
- **Perplexity**: 首页大搜索框之外,有什么引导内容(推荐问题、热门搜索)?
- **NotebookLM**: 新 Notebook 打开时,有什么引导? 怎么提示用户上传源文件?
- **Dify / AnythingLLM**: 空工作区/空项目时,页面长什么样? 有什么操作引导?

分析后给出: **适合我们场景的空状态设计建议**:
- 未登录用户看到什么?
- 已登录但没有对话历史的用户看到什么?
- 已登录有对话历史但当前项目没有内容时看到什么?

## 补充四:可以直接复用的具体 UI 模式

第1轮给出了原则,但缺少组件级别的 HTML/CSS 模式。请给出以下可以直接复用的 UI 实现思路(不需要完整代码,但需要具体到 HTML 结构级别):

### 4a. 引用角标 + 悬浮卡片
回答气泡里怎么嵌入 `[1]` 上标? 悬浮时弹出的小卡片怎么定位(跟随鼠标? 绝对定位在角标旁边? 防超出视口边缘)?

给出一个最简的 HTML 结构示例:
```html
<p>地球是太阳系第三颗行星<sup class="ref-badge" data-source="0">[1]</sup>...</p>
```
卡片用什么 HTML 结构? 怎么用 CSS `:hover` 控制显示隐藏? 移动端触屏没有 hover 怎么办?

### 4b. 深色模式 CSS 变量方案
```css
:root { --bg: #fff; --text: #222; }
[data-theme="dark"] { --bg: #1a1a1a; --text: #eee; }
```
竞品用了多少 CSS 变量? 除了背景和文字色,还需要哪些变量(消息气泡色、引用色、边框色、强调色)?

### 4c. Workspace 侧边栏结构
左侧工作区列表的 HTML 结构应该是怎样的? 当前工作区高亮、未读指示器、新建按钮的布局?

### 4d. 搜索结果的 HTML 结构
```html
<div class="search-result">
  <div class="result-title"><a href="...">文档标题</a></div>
  <div class="result-snippet">...<mark>关键词</mark>高亮...</div>
  <div class="result-meta">文件名 · 更新时间 · 置信度</div>
</div>
```
竞品在搜索结果里展示了哪些信息? 排序方式、是否分段预览?

### 4e. 底部来源卡片
Perplexity 的回答底部有个来源卡片区域,它的排版(标题+摘要+链接)在纯 CSS Grid 下怎么实现最简?

## 补充五:Dify 工作流对话界面

Dify 的对话页面有个独特设计——它可以展示「思考步骤」,类似:
```
🤔 正在理解问题...
🔍 正在检索知识库...
📝 正在生成回答...
```
这种步骤式进度展示在 RAG 场景下比单纯的"打字机"更好。请分析:

- Dify 的这个步骤进度怎么实现的?(每个步骤是一个独立的 SSE 事件? 还是前端模拟?)
- 我们能否用类似方案替代/补充现在的 reasoning panel?
- 步骤进度的 HTML/CSS 结构应该怎么设计?

## 输出格式

按以上 5 个补充顺序输出,每个补充独立章节。每个 UI 模式给出具体的 HTML 结构描述(不要完整实现代码,但要具体到标签和 class 级别)。

最终给出: **一组可以直接作为前端实现参考的 UI 设计决策**,比如:
- 引用角标: 用 `<sup>` + CSS `:hover` + 绝对定位卡片
- 深色模式: 至少 8 个 CSS 变量(更多更好)
- 搜索结果: 列表布局,包含标题/高亮摘要/元信息行
- 空状态: 3 种状态对应 3 种展示

**约束条件(与第 1 轮相同)**:
- 纯 HTML + 原生 JS,无 React/Vue/SPA 框架
- 自部署单进程(Rust + tiny_http + SQLite)
- 不能依赖外部 CDN/服务
