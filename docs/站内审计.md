# 站内审计（in-house audit）

> **不依赖 Cloudflare 的访问审计**：每个 HTTP 请求一条结构化记录，持久落盘。回答"有多少人访问了网站、什么时候、从哪个 IP、命中哪些路径、状态如何"——数据完全在你自己服务器上。
>
> 与 Cloudflare Analytics 的分工：**访客量以 CF Analytics 为准**（它统计边缘层，含被 CDN 拦截/缓存的请求，且不占服务器资源）；**本模块给的是服务器视角的精确记录**（含 status、latency、真实源 IP），两者互补。

## 1. 启用（一行配置）

```bash
# 环境变量（systemd unit 里加）
Environment=LLM_WIKI_AUDIT_DIR=/root/llm_wiki-server/audit
Environment=LLM_WIKI_AUDIT_RETENTION_DAYS=30   # 可选，默认 30，启动时清理旧文件
```

- **`LLM_WIKI_AUDIT_DIR` 未设置 = 审计完全关闭**（零开销，行为与之前完全一致）。
- 部署脚本已支持：`deploy-ecs.sh` 传 `SERVER_AUDIT_DIR=/root/llm_wiki-server/audit` 即自动注入 systemd unit（见 §5）。
- 服务器启动日志会打印：`[audit] writing access log -> /root/llm_wiki-server/audit/access-2026-08-02.jsonl`

## 2. 日志文件

```
<audit_dir>/access-YYYY-MM-DD.jsonl     # 按 UTC 日轮转
```

每条一行 JSON（追加式，一行完整，grep/awk/python 友好）：

```json
{"v":1,"ts":"2026-08-02T09:34:51.152Z","method":"GET","path":"/api/v1/health",
 "status":200,"ip":"203.0.113.9","ua":"Mozilla/5.0 ...","ms":8,"req":"d5efa06558d24fc1b2cff29c8da47dc9"}
```

| 字段 | 含义 |
|------|------|
| `v` | 格式版本（当前 1） |
| `ts` | RFC3339 UTC，毫秒精度 |
| `method` / `path` | HTTP 方法 / **仅路径**（query 永不记录，见 §3） |
| `status` | 响应状态码（2xx/3xx/4xx/5xx） |
| `ip` | 真实客户端 IP（`cf-connecting-ip` → `x-forwarded-for` → 对端地址） |
| `ua` | User-Agent（截断 256 字符） |
| `ms` | 处理耗时（毫秒） |
| `req` | request_id（与 journal 日志的 tracing span 一致，可互查） |

## 3. 隐私与安全

- **只记 path，不记 query**：`/auth/verify-email?token=...` 记为 `/auth/verify-email`，token 永不落盘。
- **永不记录请求体**（密码、聊天内容等不会出现在日志里）。
- 写失败是 best-effort（stderr 警告后继续），审计不会拖垮服务。

## 4. 看汇总（audit-summary.sh）

```bash
./scripts/audit-summary.sh ecs99             # 远端默认目录
./scripts/audit-summary.sh ecs199
./scripts/audit-summary.sh --local /tmp/audit  # 本地（开发/测试）
```

输出示例（按 UTC 日聚合）：

```
2026-08-02  req=152    uniq_ips=4    top=/api/v1/projects/xxx/search (62x)  2xx=148 4xx=3 5xx=1
TOTAL       req=152    uniq_ips(sum of days)=4
```

- `req` 当日请求数；`uniq_ips` 当日**独立访客数**（按 IP，即"有多少人访问"）；`top` 最热路径；`2xx/4xx/5xx` 状态分布。
- 环境变量可覆盖默认目录：`ECS99_AUDIT_DIR=... ./scripts/audit-summary.sh ecs99`。

## 5. 部署

```bash
# ecs99（阿里云，root）
SSH_HOST=root@47.103.39.152 SSH_PORT=22022 \
  SERVER_AUDIT_DIR=/root/llm_wiki-server/audit \
  LLM_API_KEY='...' ./scripts/deploy-ecs.sh

# ecs199（腾讯，SKIP_SYSTEMD 手动装 unit 时同样支持）
SERVER_AUDIT_DIR=/home/li/code/personal/llm_wiki-server/audit ...
```

`SERVER_AUDIT_DIR` 设置后，deploy 脚本会在 systemd unit 注入 `LLM_WIKI_AUDIT_DIR` + `LLM_WIKI_AUDIT_RETENTION_DAYS`。

## 6. 实现要点（代码走读）

- [`overlay/server/src/audit.rs`](../overlay/server/src/audit.rs)：`AuditLog`（Mutex<File> + 按日轮转 + 启动清理）、`Entry`、`thread_local LAST_STATUS`、手写 civil-from-days 日期/RFC3339（无 chrono 依赖）、真实 IP 头解析。
- **状态码采集方式**：respond 辅助函数（`respond_json`/`respond_with_cookie`/`respond_options`/直接 respond 处）把最终状态码写进**线程本地**，dispatch 完成后读回。安全的前提是 server 每请求一个独立线程（线程本地天然按请求隔离）；若未来改异步模型需迁移为显式传值。
- 挂钩点：[`overlay/server/src/server.rs`](../overlay/server/src/server.rs) 的 `run()` 循环——派发前提取 `path`（去 query）/`ip`/`ua`/`req_id`，派发后（含 panic→500）读状态码落盘；循环级早退（503/429/503）直接记录已知状态。
- 审计功能对未启用的部署**零侵入**：`LLM_WIKI_AUDIT_DIR` 未设置时 `Option<AuditLog>` 为 `None`，所有调用是 no-op。
