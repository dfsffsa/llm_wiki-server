# 后端功能借鉴分析

基于竞品代码分析,聚焦与 Rust + SQLite 单进程架构匹配的模式。

---

## 可借鉴的

### 1. SSE 事件层次设计(最有价值)

当前事件: `reasoning` / `token` / `done` / `error`

可以扩展为:

| 事件 | 作用 | 前端响应 |
|---|---|---|
| `reasoning_start` | 推理开始 | 打开 thinking panel,清空旧内容 |
| `reasoning_delta` | 推理 token(现 `reasoning`) | 追加到 thinking panel |
| `reasoning_done` | 推理结束 | 关闭 thinking panel,或标记完成 |
| `citation_info` | 引用文档信息 | 预加载引用数据,可提前渲染来源 |
| `token` | 回答 token(不变) | 追加到回答气泡 |
| `done` | 完成(不变) | 结束流式,渲染来源卡片 |

**改动量**:Rust `chat.rs` 的 SSE 流加 3 个新事件类型,前端 `parseSseChunk` 增加对应处理。约半天。

### 2. 引用数据流设计

```
用户输入 → 搜索检索 → 文档列表 → LLM 生成回答(含 [N] 引用)
                                                ↓
                                           引用编号压缩
                                        (collapse_citations)
                                                ↓
                                       前端渲染 [N] 为可交互角标
```

关键模式:后端在 LLM 返回完整回答后,扫描文本中的 `[N]` 标记,与检索到的文档列表做映射,生成 `citation_mapping {编号→文档ID}`。这个映射和回答一起发给前端。

当前我们没做这一步——检索结果直接作为 LLM 上下文,前端只能靠 `window.__lastSources` 来匹配。加上这步可以让前端拿到"这个回答确切引用了哪些文档"。

### 3. 搜索结果统一数据结构

搜索、RAG 上下文、引用展示共用一个数据结构:

```
SearchResult:
  doc_id: string        # 文档标识
  title: string         # 可读标题
  link: string          # 原文链接
  snippet: string       # 高亮摘要
  score: float          # 相关度
  chunk_ind: int        # 分块索引
```

我们已有类似结构(在 search API 返回中),但前端 `buildContext()` 之前把结构化数据压成了纯文本传给 LLM。已修正在 `buildContext` 改造中(`{text, sources}`)。

### 4. 多轮消息树(按需)

```
user msg → assistant msg → user msg →
          ↘ assistant msg (重生成)
```

支持分支重生成,需要存储 `parent_message_id`。目前我们是线性列表,如果要做"重新生成"功能可参考。

## 不好借鉴(架构差异大)

| 模式 | 对方实现 | 我们架构不匹配的原因 |
|---|---|---|
| Celery 异步任务 | Python 多 Worker | 单进程 Rust,async/await 足够 |
| PostgreSQL 向量搜索 | PG + pgvector | SQLite + LanceDB |
| 连接器框架(30+) | 统一接口 + 各自同步逻辑 | 只 ingest markdown 目录 |
| Agent 编排 | MCP + 代码解释器 + Web 搜索 | 不需要 |
| 多租户权限 | 用户/团队/角色层级 | 个人/家庭场景 |
| SSO/OAuth/OIDC | 完整企业认证 | 邮箱密码够了 |

## 建议优先级

| # | 模式 | 工作量 | 价值 |
|---|---|---|---|
| P0 | `reasoning_start/done` + `citation_info` SSE 事件 | ~半天 | 高 |
| P1 | `citation_mapping` 后端输出 | ~半天 | 中 |
| P2 | 引用编号压缩 `collapse_citations` | ~半天 | 中 |
| P3 | 消息树支持(重生成) | ~1天 | 低 |
